# AGENTS.md

This repository is the TaxWise application: a full-stack tax filing assistant with a Next.js frontend and a FastAPI backend.

## Project map

- [README.md](README.md) — high-level overview and quick start
- [docs/dev-guide.md](docs/dev-guide.md) — developer reference and architecture notes
- [docs/API.md](docs/API.md) — backend API contracts and routes
- [docs/TAX_ENGINE.md](docs/TAX_ENGINE.md) — tax computation details and business rules
- [docs/DOCUMENT_INTELLIGENCE.md](docs/DOCUMENT_INTELLIGENCE.md) — document processing and extraction
- [backend/](backend/) — FastAPI app, SQLAlchemy models, routes, services, tax engine
- [frontend/src](frontend/src) — page components, API client, auth state, UI logic

## Working conventions

- Prefer small, domain-focused changes. Keep backend business logic in the relevant service/module, not in route handlers.
- Follow the existing structure: routes in [backend/routes](backend/routes), schemas in [backend/schemas](backend/schemas), persistence in [backend/models](backend/models), and tax logic in [backend/tax_engine](backend/tax_engine).
- Frontend code belongs under [frontend/src](frontend/src), especially pages, components, store, and lib.
- Maintain the existing FastAPI + Pydantic + SQLAlchemy patterns. Reuse validation and model schemas instead of creating parallel ad hoc structures.
- When updating behavior, check the relevant docs first and avoid re-writing already documented rules.

## Build and validation commands

### Backend

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m pytest
```

### Frontend

```bash
cd frontend
npm install
npm run type-check
npm run build
```

### Full local stack

```bash
cd taxwise
docker compose up --build
```

## Important project-specific notes

- The app is structured for a tax workflow: authentication, tax profile forms, document handling, onboarding, and tax calculation.
- Database setup is expected to use PostgreSQL and is configured through [docker-compose.yml](docker-compose.yml) and [backend/config.py](backend/config.py).
- API documentation is generated by FastAPI at /docs when the backend is running.
- The tax engine is intentionally business-rule heavy; changes here should be checked against [docs/TAX_ENGINE.md](docs/TAX_ENGINE.md) and the related tests under [backend/tests](backend/tests).
- Prefer repo-native patterns and naming over introducing new framework-layer conventions.

## When contributing

- Keep changes scoped and easy to review.
- Update tests when fixing or extending behavior.
- Prefer explicit schemas, validated inputs, and documented assumptions.
- If you need broader context, read the matching docs before editing implementation.
